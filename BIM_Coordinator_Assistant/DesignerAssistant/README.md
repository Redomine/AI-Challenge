# Помощник BIM-координатора

Консольный агент на .NET 8 и GigaChat для технического саппорта, проверки
BIM-моделей, плагинов и скриптов. История и явные слои памяти сохраняются в
SQLite. Данные Revit читаются и изменяются через `rvt-mcp`.

## Запуск

Из папки `BIM_Coordinator_Assistant\DesignerAssistant`:

```powershell
dotnet run --project '.\DesignerAssistant.csproj'
```

Ярлык `Запустить BIM-помощника.lnk` в папке `BIM_Coordinator_Assistant`
запускает веб-интерфейс и оставляет окно сервера открытым.
Веб-интерфейс доступен по адресу `http://127.0.0.1:5199`.
Ярлык `Выключить BIM-помощника.lnk` рядом с ним завершает только процессы
`DesignerAssistant.Web`, запущенные из этого проекта.

## Вопросы по базе знаний

В разделе `RAG-чат` можно задать вопрос в режиме `RAG` (Ollama считает
эмбеддинг, приложение ищет фрагменты в локальном SQLite-индексе и передаёт
их выбранной модели) или `без RAG` (та же модель без поиска). Ответ RAG показывает
фактические метаданные найденных фрагментов. Инструменты Revit в этих режимах
не вызываются.

По умолчанию используются файлы `Выгрузка страниц\index_out\structural.sqlite3`
и `Выгрузка страниц\index_out\questions.json` на рабочем столе текущего
пользователя. Пути можно переопределить переменными `RAG_INDEX_PATH` и
`RAG_QUESTIONS_PATH`. По умолчанию ответы формирует локальная `qwen3:4b`
через Ollama; ключ GigaChat не нужен.

В основном чате кнопки `Qwen` и `GigaChat` переключают провайдера для текущей
сессии. Для GigaChat нужен `GIGACHAT_AUTH_KEY`. Переключение недоступно во время
активной задачи. В RAG-чате есть отдельный выбор `Qwen`/`GigaChat`;
поиск и эмбеддинги в обоих случаях остаются локальными. Mini-чат использует Qwen.
Кнопка `Сравнить модели` запускает вопросы Дня 24 через оба провайдера с
одинаковыми настройками RAG и показывает ответы, качество, время и стабильность.
Без ключа GigaChat RAG и автотест продолжают работать только с Qwen.
Правая панель основного чата сохраняет ход задачи: план, фактические результаты
инструментов и проверку. Если модель отдельно вернула рассуждения, они
показываются отдельной записью. Qwen передаёт их через Ollama `message.thinking`,
GigaChat — через `reasoning_content`. У Qwen в структурированных запросах
`think` отключён, чтобы ответ содержал обязательный JSON-план или проверку. Запрос
GigaChat с `functions` и `reasoning_effort` при проверке вернул HTTP 500,
поэтому вызовы инструментов идут без этого параметра; для такого ответа
отдельные рассуждения могут не поступить.
Адрес локального API и модель задаются через `DESIGN_ASSISTANT_OLLAMA_URL`
(по умолчанию `http://127.0.0.1:11434`) и `DESIGN_ASSISTANT_OLLAMA_MODEL`
(по умолчанию `qwen3:4b`).

### День 29: сравнение профилей Qwen

Кнопка `Тест оптимизации` в основном чате последовательно запускает базовый и
оптимизированный профили на живом агенте/Revit 2022: открыть указанную RVT,
синхронизировать локальную копию с центральной и закрыть. Только внутри этого
теста открытие указанного RVT и синхронизация с закрытием автоматически
подтверждаются после проверки инструмента, аргументов и сеанса Revit. Другие
изменяющие вызовы не подтверждаются.
Результат включает завершённость MCP-вызовов, проверку фактического закрытия,
время и пиковые снимки RAM процессов Ollama и общей занятой VRAM GPU.
При сбое после изменяющего вызова второй прогон не начинается автоматически.

Базовый профиль сохраняет `num_predict=1200`, `num_ctx=16384` и температуру
модели. Оптимизированный использует `temperature=0.1`, `num_predict` не ниже
1800, `num_ctx=24576` и дополнительные инструкции для плана, выполнения и
проверки Revit/MCP. Квантование не меняется.

Для проверки трёх запросов через клиент приложения из папки
`BIM_Coordinator_Assistant\DesignerAssistant.Web` выполните:

```powershell
dotnet run --no-launch-profile -- --llm-smoke
```

Команда выводит три JSON-строки с вопросами и фактическими ответами Qwen.

Кнопка `Запустить автотест` прогоняет 10 вопросов из `questions.json` в обоих
режимах. Проверка считает точное наличие всех `expected_fact_terms` в ответе
и соответствие источника, страницы PDF и раздела метаданным поиска. Это
строгая автоматическая проверка терминов, а не семантическая оценка ответа.
Для повторного запуска без интерфейса из папки
`BIM_Coordinator_Assistant\DesignerAssistant.Web` выполните:

```powershell
dotnet run --no-launch-profile -- --run-rag-eval
```

Результат: JSON-отчёт `rag-evaluation-*.json` рядом с файлом вопросов; в нём
только оценки по пунктам, без ответов и текстов документов.

Для режима GigaChat должна быть зарегистрирована переменная `GIGACHAT_AUTH_KEY`.
Его значения по умолчанию: scope `GIGACHAT_API_PERS`, модель `GigaChat-2-Max`, токенизатор `GigaChat`.

## MCP для журнала и уведомлений

Из папки `BIM_Coordinator_Assistant` сначала соберите служебные MCP-серверы:

```powershell
dotnet build '.\AssistantOps.Mcp\AssistantOps.Mcp.csproj'
```

Эта сборка создаёт `AssistantOps.Mcp.dll`. Помощник запускает два отдельных
stdio-процесса этого модуля: `log-mcp` и `ops-mcp`. Вместе с `rvt-mcp` они
появляются в общем каталоге инструментов. Путь к DLL можно переопределить
через `DESIGN_ASSISTANT_OPS_MCP_DLL`.

`log-mcp` сохраняет время, тип события, имя вызванного инструмента, итог и
длительность в `%LOCALAPPDATA%\DesignerAssistant\audit.jsonl`. Аргументы
инструментов, ответы Revit и секреты в автоматический журнал не записываются.
Для другого пути задайте `DESIGN_ASSISTANT_AUDIT_PATH`. Инструмент
`log_recent_events` читает последние 1-100 записей. `ops_heartbeat` показывает
состояние служебного процесса.

Письма о завершении и ошибке задачи отправляются на фиксированный адрес,
если настроены переменные окружения:

- `DESIGN_ASSISTANT_MAIL_TO` — адрес получателя;
- `DESIGN_ASSISTANT_MAIL_FROM` — адрес отправителя;
- `DESIGN_ASSISTANT_SMTP_HOST` — SMTP-сервер;
- `DESIGN_ASSISTANT_SMTP_PORT` — порт, по умолчанию 587;
- `DESIGN_ASSISTANT_SMTP_USER` и `DESIGN_ASSISTANT_SMTP_PASSWORD` — учётные данные.

SMTP использует TLS. Пароль не хранится в репозитории. Пока адрес и SMTP не
заданы, фактической отправки нет. `ops_send_notification` принимает только
тему и текст, получатель берётся из настройки сервера.

Для проверки веб-интерфейса без запуска просроченных периодических задач из
папки `BIM_Coordinator_Assistant\DesignerAssistant.Web`:

```powershell
$env:DESIGN_ASSISTANT_DISABLE_SCHEDULER = '1'
dotnet run --urls 'http://127.0.0.1:5080'
```

Результат — веб-интерфейс на порту 5080 без фонового выполнения расписания.

Для задачи обновления шаблонных семейств в расписании закреплена цель Revit 2022.
Её текст просит агента сообщать количество обработанных, загруженных,
неизменённых и неудачных семейств, а также пути и ошибки из ответа MCP.
Планировщик не содержит проверок, специальных для семейств: он сохраняет
результат выполнения через `log-mcp` и при успешном завершении отправляет
письмо через `ops-mcp`. Требования к конкретной операции задаются в тексте
задачи для агента.

Для однократного ручного запуска именно этой сохранённой задачи из папки
`BIM_Coordinator_Assistant\DesignerAssistant.Web`:

```powershell
$env:DESIGN_ASSISTANT_DISABLE_SCHEDULER = '1'
dotnet run -- --run-scheduled 503cc8c5-7c58-4446-858b-56953f03f21b
```

Команда выполняет задачу один раз и обновляет её результат и следующее время
запуска в `scheduled-tasks.json`; для SMTP переменные окружения должны быть
доступны процессу при старте.

Перезапуск: введите `/exit` или нажмите `Ctrl+C`, затем снова выполните `dotnet
run`. История и явная память восстановятся из SQLite.

## Веб-интерфейс

Blazor Server-интерфейс использует то же ядро агента и ту же SQLite-базу. Из
папки `BIM_Coordinator_Assistant` выполните:

```powershell
dotnet run --project '.\DesignerAssistant.Web\DesignerAssistant.Web.csproj'
```

Откройте адрес, который приложение выведет в строке `Now listening on`.
Эту же команду выполняет ярлык `Запустить BIM-помощника.lnk`.
Интерфейс содержит чат, профили, базовый prompt в режиме только для чтения,
слои памяти, выбор сеанса Revit и отдельное подтверждение каждой операции,
изменяющей модель. Консольная версия продолжает
работать независимо. После запроса блок `Диагностика инструментов` показывает
маршрут, фактический MCP-вызов и результат; явные запросы по `ElementId` и об
активном виде маршрутизируются локально без дополнительного LLM-вызова.

## Модель памяти

Контекст формируется в фиксированном порядке: базовая системная инструкция,
долговременная память, рабочая память, активный профиль пользователя, последние
N сообщений и текущий вопрос. Внутри системной инструкции профиль расположен
последним приоритетным блоком и явно отделён от памяти.

## Профиль пользователя

По умолчанию профили отсутствуют и приложение не создаёт пользователя
автоматически. Можно создать несколько именованных профилей. Для управления
используется интерактивный мастер:

```text
/profile create
/profile edit
/profile show
/profile select
/profile select BIM-координатор
/profile delete
```

Профиль содержит три свободных текстовых блока без обязательных полей:

- `Style` — желаемый стиль и формат ответа;
- `Constraints/Tooling` — инструменты, стек, ограничения и правила;
- `Context` — любой полезный пользовательский и проектный контекст.

После создания профиль автоматически включается в системную инструкцию каждого
запроса. Каждый блок поддерживает многострочный ввод и завершается отдельной
строкой `.`. При редактировании сразу введённая `.` сохраняет прежний блок, а
`-` очищает его. `/profile select` показывает список и отмечает активный профиль.
Последний выбор сохраняется в SQLite и восстанавливается после перезапуска.
Удаление требует подтверждения.

Указания активного профиля считаются постоянной просьбой пользователя и целиком
имеют приоритет над конфликтующими правилами базового prompt. Это относится ко
всем инструкциям профиля, а не только к языку или стилю ответа.

Профиль включается в контекст основного агента до выбора MCP-инструмента.
После выполнения задачи отдельный универсальный проход
проверяет черновик по всем блокам профиля и формирует итоговый ответ, сохраняя
фактические результаты Revit. При активном профиле это расходует дополнительный
запрос к GigaChat.

### Краткосрочная

Текущий диалог: сообщения пользователя и ответы агента. Он восстанавливается
после перезапуска и очищается командой `/clear`. Явные слои сохраняются.

### Рабочая

Данные текущей задачи или проекта: цель проверки, модель, версия и сеанс Revit,
плагин, шаги воспроизведения, временные гипотезы, результаты и `ElementId`.
Очищается через `/task complete`. `ElementId` нельзя переносить в долговременную
память, поскольку он относится к конкретному документу.

```text
/remember work model=Coordination_Test.rvt
/remember work issue=Не создаётся спецификация
```

Catch-фразы рабочей памяти:

```text
запомни для этой задачи ...
сохрани для текущей задачи ...
запомни в рабочую память ...
на время этой задачи ...
для этого проекта запомни ...
до завершения задачи запомни ...
```

### Долговременная

Устойчивые решения и правила: поддерживаемые версии Revit, утверждённые
соглашения, повторно используемые знания и политика безопасности. Профиль
пользователя хранится отдельно. Долговременная память сохраняется между
диалогами и задачами.

```text
/remember long role=BIM-координатор
/remember long report_format=Краткий маркированный список
```

Catch-фразы долговременной памяти:

```text
запомни на будущее ...
запомни долговременно ...
запомни навсегда ...
сохрани в долговременную память ...
всегда помни ...
учитывай в дальнейшем ...
это постоянное правило ...
```

Неоднозначное `запомни ...`, `сохрани ...`, `запиши ...` или `учти ...` вызывает
выбор: рабочая память, долговременная память либо отмена. Агент не выбирает слой
молча.

Сохранённые записи передаются GigaChat с каждым вопросом:

```text
Что у нас зафиксировано для этого проекта?
Какие постоянные правила ты учитываешь?
Что известно о текущей задаче?
```

## Revit и native function calling

Один основной агент GigaChat получает актуальные схемы MCP и выбирает функции в
bounded loop. Отдельного семантического `ToolRouter` перед ним нет. Чтение
выполняется автоматически. Перед каждой транзакцией приложение показывает
инструмент, цель и аргументы; операция выполняется только после точного ответа
`да`. `send_code_to_revit` и ToolBaker запрещены.

Вопросы о названиях, назначении и параметрах доступных инструментов отвечаются
по уже загруженному каталогу и не должны запускать MCP-команду или запрашивать
разрешение на транзакцию. Вопросы о функционале, возможностях активного вида и
операциях с элементами распознаются локально и получают сгруппированное русское
описание актуального каталога без отдельного LLM-вызова. Каталог также
передаётся финальной проверке профиля.

Policy/execution layer проверяет наличие функции в текущем `tools/list`, JSON
Schema, классификацию и подтверждение, затем возвращает агенту структурированный
result envelope. Ошибка или отмена останавливает ветку; `queued` и `posted` не
считаются завершением. Каждый новый пользовательский запрос по умолчанию начинает
task state machine со стадии Planning и требует согласования плана.

По умолчанию диагностика инструментов скрыта, ошибки видны всегда. Подробности
включаются через `/debug on`.

Перед работой выберите сеанс:

```text
/revit select
/revit select 61544
```

Имя имеет вид `REVIT-2022 [Имя проекта.rvt]`, ID — PID процесса.

### Несколько Revit одного года

`rvt-mcp 0.6.1` создаёт один `revit-YYYY.json` на год. Последний Revit данного
года, запустивший transport, заменяет файл своими PID, портом и токеном. Поэтому
из нескольких Revit одного года маршрутизируется только PID с `[доступен]`.

Безопасный порядок:

1. остановить MCP transport во всех окнах этого года;
2. запустить его только в нужном окне;
3. выполнить `/revit select`;
4. выбрать PID с отметкой `[доступен]`;
5. не запускать transport в других окнах этого года во время работы агента.

`MCP is running` в Ribbon означает, что listener окна работает. Фактическое
подключение внешнего клиента показывает строка `Client connected`.
