# День 11. Память помощника BIM-координатора

## Цель

Перевести приложение с роли «Помощник проектировщика» на роль персонального
технического помощника BIM-координатора. Агент должен помогать пользователю с
саппортом, диагностикой и тестированием моделей, плагинов и скриптов, вести
диалог через GigaChat, хранить три явно разделённых слоя памяти и получать
актуальные данные открытой модели через `rvt-mcp`, не подменяя результаты Revit
предположениями модели.

Первая версия работает только на чтение. Изменения модели включаются отдельным
этапом после проверки сценариев чтения и всегда требуют подтверждения человека.

## Архитектура

```text
Пользователь
    |
    v
BIM Coordinator Agent (.NET 8)
    |-- GigaChat: рассуждение, выбор инструмента, итоговый ответ
    |-- IMemoryStore: short-term / working / long-term
    `-- IMcpClient: MCP stdio
            |
            v
        rvt-mcp 0.6.1
            |
            +-- TCP localhost -> Revit 2022 plugin -> Revit API
            `-- TCP localhost -> Revit 2024 plugin -> Revit API
```

`rvt-mcp` установлен локально и зарегистрирован в Codex в безопасном режиме:

```toml
[mcp_servers.rvt-mcp]
enabled = true
command = 'C:\Users\Mankaev_r\AppData\Local\RvtMcp\rvt\server\0.6.1\rvt-mcp.exe'
args = ["--read-only", "--disable-toolbaker"]
```

Наше приложение использует отдельный MCP-клиент с теми же аргументами. Оно не
зависит от конфигурации Codex и не вызывает `rvt-mcp` через оболочку.

## Роль агента

Помощник BIM-координатора:

- помогает разбирать обращения пользователей и воспроизводить проблемы;
- анализирует состав, параметры и состояние BIM-модели;
- проверяет активный документ, вид, выборку и рабочие наборы;
- помогает тестировать плагины, pyRevit-скрипты и сценарии работы с моделью;
- фиксирует тестовую среду, шаги воспроизведения, ожидаемое и фактическое
  поведение;
- сопоставляет факты из Revit, журналы и наблюдения с условиями текущей задачи;
- помогает локализовать причину проблемы, не выдавая гипотезу за подтверждённый
  результат;
- готовит краткий технический отчёт с идентификаторами элементов, версией Revit
  и источником каждого факта;
- не утверждает, что видел или изменил модель, без успешного результата MCP;
- не выполняет изменение модели без явного подтверждения пользователя.

## Слои памяти

| Слой | Данные BIM-координатора | Срок жизни | Хранилище |
|---|---|---|---|
| Краткосрочная | Последние реплики, последние результаты MCP и уточнения | Текущий диалог | `short_term_messages` |
| Рабочая | Текущее обращение или тест: среда, версия плагина, шаги воспроизведения, ожидаемое и фактическое поведение, целевой Revit, документ, вид, выборка и гипотезы | До завершения задачи | `working_memory` |
| Долговременная | Профиль пользователя, стандарты компании, особенности поддерживаемых версий Revit, известные плагины, подтверждённые решения и формат отчёта | Между сессиями | `long_term_memory` |

Данные разных слоёв хранятся отдельно. Ответ MCP не записывается автоматически в
долговременную память.

## Модели данных

```csharp
public enum MemoryLayer
{
    ShortTerm,
    Working,
    LongTerm
}

public enum MemorySource
{
    User,
    RevitMcp,
    Agent
}

public enum EvidenceStatus
{
    Reported,
    Observed,
    Hypothesis,
    Confirmed
}

public sealed record MemoryEntry(
    long Id,
    MemoryLayer Layer,
    string Key,
    string Value,
    MemorySource Source,
    EvidenceStatus Status,
    string? TaskId,
    DateTimeOffset CreatedAt,
    DateTimeOffset UpdatedAt);

public sealed record RevitTarget(
    int Year,
    int ProcessId,
    string? DocumentIdentity,
    string? DocumentTitle);
```

`ChatMessage` остаётся только единицей диалога. Структурированная память не
хранится в тексте сообщений.

`DocumentIdentity` должен строиться из устойчивых доступных признаков документа,
а не только из заголовка окна. Результаты, содержащие `ElementId`, всегда
связываются с документом, версией Revit и текущей задачей.

## Ограничения хранения Revit-данных

1. `ElementId`, активный вид, выборка и PID процесса хранятся только в рабочей
   памяти.
2. Перед повторным использованием `ElementId` агент проверяет целевой процесс и
   идентичность документа через MCP.
3. Закрытие или смена документа делает сохранённые идентификаторы элементов
   неактуальными и очищает соответствующий рабочий контекст.
4. Результаты MCP получают `Source = RevitMcp` и время чтения.
5. Вывод GigaChat не становится фактом Revit без подтверждающего MCP-вызова.
6. В долговременную память не записываются пути моделей, параметры элементов и
   содержимое проекта без явного решения пользователя.
7. Причина сбоя остаётся `Hypothesis`, пока её не подтвердил повторяемый тест,
   журнал, результат MCP или пользователь.

`CallReadToolAsync` применяет allowlist. В первой версии разрешены, например:

```text
revit_list_available_targets
```

`revit_send_code_to_revit` и все изменяющие инструменты запрещены независимо от
решения GigaChat.

## Явная запись в память

1. Каждая успешная пара `user/assistant` сохраняется только в краткосрочную
   память.
2. `/remember work <key> <value>` записывает условие текущего обращения или
   теста в рабочую память: окружение, шаг, наблюдение, ожидание или гипотезу с
   явно указанным статусом.
3. `/remember long <key> <value>` записывает подтверждённое постоянное правило.
4. Результат MCP сохраняется в рабочую память только тогда, когда он нужен для
   следующих шагов текущей задачи.
5. `/task complete` удаляет рабочую память задачи, включая `ElementId`.
6. `/clear` очищает только краткосрочную память.
7. `/memory` показывает слой, источник, задачу и время обновления записи.

Автоматически извлечённый GigaChat факт можно показать как предложение, но нельзя
сохранять в долговременную память без явного подтверждения пользователя.

## Команды BIM-координатора

```text
/revit select                  показать полные имена сеансов и ID
/revit select <ID|имя>         выбрать конкретный сеанс
/revit status                  показать процесс, документ и активный вид
/revit selection               прочитать выбранные элементы
/memory                        показать три слоя памяти
/history                       показать восстановленный диалог
/help                          показать все доступные команды
/remember work <key> <value>   сохранить условие текущей задачи
/remember long <key> <value>   сохранить постоянное правило
/clear                         очистить текущий диалог
/task complete                 завершить задачу и очистить рабочую память
```

После перезапуска приложение загружает сохранённые сообщения текущего диалога из
SQLite и выводит их в консоль до первого приглашения ввода. Команда `/history`
повторно показывает восстановленный диалог. Напоминание `/help — команды`
присутствует в каждом приглашении ввода, а `/help` перечисляет только реально
реализованные команды.

Если одновременно запущены Revit 2022 и 2024, агент не выбирает цель молча. До
первого модельного запроса он вызывает `revit_list_available_targets` и просит
выбрать версию либо использует уже явно сохранённую цель текущей задачи.

## Сборка контекста GigaChat

Перед ответом агент формирует контекст в следующем порядке:

1. системная инструкция помощника BIM-координатора;
2. разрешённые MCP-инструменты и правила их применения;
3. долговременная память;
4. рабочая память текущей задачи;
5. последние N сообщений краткосрочной памяти;
6. новый вопрос пользователя.

Рабочая память имеет приоритет над долговременной. Свежий успешный результат MCP
имеет приоритет над сохранённым рабочим значением. Конфликт показывается
пользователю, а не разрешается скрыто.

Диагностический режим выводит `Memory context` и `Tool trace`: выбранные записи,
имя MCP-инструмента, целевой Revit, аргументы без секретов, длительность и статус.
Токен discovery-файла, ключ GigaChat и полная системная инструкция не выводятся.

## Проверка через GigaChat и живой Revit

Проверка выполняется на тестовой модели, не на рабочей центральной модели. Revit
2022 и Revit 2024 запускаются одновременно, чтобы проверить явную маршрутизацию.

### Сценарий

```text
/remember long report_style краткий список с ElementId
/revit select
/revit select <ID>
/revit status
/revit selection
Что выбрано, какие параметры доступны и достаточно ли данных для воспроизведения проблемы?
/clear
Какой формат отчёта нужно использовать?
/task complete
/memory
```

### Проверяемые результаты

1. `/revit select` возвращает полные имена сеансов и разные PID.
2. После `/revit select <ID>` запросы не уходят в другой Revit.
3. Выбранные `ElementId` появляются только в рабочей памяти и содержат привязку
   к документу и версии Revit.
4. Ответ GigaChat ссылается только на факты, реально возвращённые MCP.
5. После `/clear` исчезает история диалога, но цель задачи и формат отчёта
   остаются.
6. После `/task complete` удаляются цель Revit, документ, выборка и `ElementId`,
   а долговременный формат отчёта сохраняется.
7. При переключении документа старые `ElementId` отклоняются как неактуальные.
8. В `read-only` отсутствуют `revit_send_code_to_revit`, create/modify/delete и
   попытка GigaChat вызвать их блокируется приложением.
9. `Tool trace` показывает реальную версию Revit и статус каждого вызова.
10. Один вопрос повторяется с заполненной памятью и после очистки каждого слоя;
    в отчёте сравниваются контекст, ответ GigaChat и расход токенов.

## Этапы реализации

1. Переименовать пользовательские тексты и системный prompt в «Помощник
   BIM-координатора».
2. Реализовать раздельные таблицы памяти и явные команды управления слоями.
3. Добавить MCP-клиент и allowlist инструментов чтения.
4. Реализовать выбор между Revit 2022 и 2024 и проверку идентичности документа.
5. Добавить `Memory context` и `Tool trace` без секретов.
6. Выполнить сценарий на живых тестовых моделях обеих версий.
7. Только после успешной проверки спроектировать подтверждаемые операции записи
   через отдельный allowlist и одну отменяемую транзакцию.
